## 0. Cos'è il progetto (in una riga)

**football-deep-analyzer** = portale personale, gratuito e automatico di **analisi calcistica profonda**: per ogni partita produce previsioni probabilistiche calibrate (xG, Dixon-Coles, Elo, ensemble), indisponibili, arbitro, meteo, contesto e report **in italiano** pre/post partita. Le quote bookmaker non sono un obiettivo editoriale. Tutto gira su GitHub Actions (cron) e viene pubblicato su GitHub Pages; i dati sono versionati nel repo (Parquet + DuckDB).

## 1. Architettura e flusso (niente server, costo zero)

```
GitHub Actions (cron 5x/giorno) → collect (FotMob/ESPN/Understat/mirror) →
  Parquet in data/processed + DuckDB → predict (DC + Elo + xG) →
  build (sito statico in site/) → commit dati → deploy GitHub Pages
```

- Il comando che fa tutto è `fda daily` = `collect → calibrate → predict → backtest → simulate → build` (la calibrazione si stima sui dati del run precedente, solo passato; se fallisce il run degrada al modello grezzo invece di bloccarsi).
- Il sito è **statico**: `index.html` (Oggi), `prossime.html`, `risultati.html`, `partite/<id>.html` (tutte le finite di stagione, archivio), `giocatori/` (hub + tabellone per lega + schede giocatore con percentili/radar, fase 3), `accuratezza.html` (RPS/Brier reali), `stagione.html` (proiezioni), `stato.html` (stato fonti). Report in italiano generati dai template `analysis.py` → `narrative`.
- Il pacchetto è installabile: `pip install -e ".[dev]"`; entry point CLI `fda` (typer).

### Ricerca modelli di previsione, calibrazione e incertezza 2026-09-13
- **Quale famiglia di modelli** (pena.lt 10/03/2025, autore di `penaltyblog`; fetch 404, letto via ricerca): DC ≈ copula di Weibull (RPS 0,19138/0,19141) > Poisson ≈ zero-inflazionata (0,19154) > binomiale negativa (0,19156) > Poisson bivariata (0,19162); ~4 stagioni di storico; ξ da tarare **per lega** (Eredivisie 0,191→0,189 con ξ=0,001). Conferma incrociata su opisthokonta.net: la famiglia migliore cambia per lega/periodo (ξ≈0,0021 EPL, 0,0015 Bundesliga) → tutte queste varianti sono candidati del laboratorio, non scelte a priori.
- **Contro l'entusiasmo ML**: Fischer & Heuer, arXiv:2408.08331 (letto) — la scelta esatta di feature/modello ha influenza **minore**; i livelli di prestazione non cambiano sistematicamente dentro la stagione. Priorità quindi a correggere i difetti misurati e a confrontare famiglie semplici con protocollo serio.
- **Struttura sui mercati dei gol**: arXiv:2103.07272 (Mar-Co) — in Dixon-Coles ρ **non** può cambiare le probabilità Over/Under, la copula sì → primo sostituto strutturale se i mercati restano distorti dopo la calibrazione. JRSS-C 74(3): binomiale negativa bivariata leggermente meglio del Poisson indipendente; shrinkage κ delle probabilità estreme utile.
- **Ensembling/stacking**: Hubáček & Groll (MLS 2017 challenge, doi:10.1007/s10994-018-5741-1) e Journal of Big Data 2024 (Eredivisie) — ensemble e calibrazione raccomandati; il Poisson log-linear gerarchico ≈ il miglior Bradley-Terry. Da qui la miscela **nella griglia** (`_mix_grids`) invece che solo sul vettore 1X2, e `convex_weights` per lo stacking convesso senza dipendenze nuove.
- **xG come segnale**: repliche IJtsma/American Soccer Analysis ed Elhabr 2024 — il rapporto xG(+xA) batte i punti nella previsione dei punti futuri già a ~7-10 gare; xGOT peggio di xG; regressione di Poisson in CV: media xG meglio della media gol (MSE 1,35 vs 1,38). Limite nostro: lo storico xG nel repo copre solo la stagione corrente → serve accumulo prima del candidato `dc_xg`.
- **Modelli dinamici/Bayesiani** (Rue-Salvesen 2000; Koopman-Lit state-space; Egidi 2018; Baio-Blangiardo 2010 con over-shrinkage; pacchetto R `footBayes`, preprint 2026: DC dinamico pesato RPS 0,192 EPL / 0,146 LaLiga): piano P3, richiede runtime Bayesiane (`numpyro`/`jax`, non installate) e il mercato delle quote resta davanti a metà stagione.
- **In-play** (Robberechts KDD 2021 RPS 0,1338; arXiv:2605.16066 Weibull-AFT con PSxG RPS 0,1294; Maia 2025: espulsione −30% intensità, rimonta +10/20%): fuori perimetro, il sito è statico e la curva in-play resta dichiarata come ricostruzione.
- **Infortuni/assenze**: trovate solo fonti di settore (effetto dichiarato 8-15% sulla probabilità di vittoria, xGA più sensibile alle assenze difensive) → se si useranno, etichetta **[presunto]** e misura prima della pubblicazione.
- **Comunicare l'incertezza** (Kay CHI 2016, Hullman TVCG 2015): i **quantile dotplot** hanno varianza di lettura ~1,15× più bassa delle densità, subitizing fino a ~5 punti, il framing a frequenze («1 su 10») batte le percentuali; palette colorblind-safe (Okabe-Ito) e contrasto WCAG 4,5:1 → barre in «partite su 100» + 20 punti da 5 partite, con numeri scritti e `aria-label`.
- **Riutilizzabile**: `penaltyblog` (già in `pyproject.toml`) espone API uniforme `fit()/predict()` per tutte le famiglie qui sopra; tempi di fit su 720 gare: DC/Poisson/NegBin/ZIP ~0,02 s, bivariata 0,07 s, **Weibull 1,23 s** → motivo per cui il laboratorio sta in un workflow settimanale e non nel daily. Attenzione: `create_dixon_coles_grid` di penaltyblog ha le celle τ scambiate, si usa solo `models/dc_grid.py`.
